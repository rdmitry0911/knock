# Knock Control 4

[Скачать релиз 4.0.3](https://github.com/rdmitry0911/knock/releases/tag/v4.0.3): подписанный Mozilla XPI, Chromium ZIP, Linux DEB/RPM, OpenWrt APK и исходники.
Установка и сборка deb/rpm описаны в [руководстве по Linux-пакетам](doc/LINUX_PACKAGES.md).

В расширении оставлены **ON, OFF, импорт, выбор и удаление профилей**. Настройки,
проверка статуса и HTTPS-режим удалены. На сервере нет API, TLS, CGI или отдельного
uhttpd: открывать TCP 8443 не требуется. Браузер отправляет подписанный UDP knock
через WebRTC ICE, daemon перехватывает пакет через libpcap без слушающего сокета.
Закрытие окна расширения не прерывает уже начатую передачу.

## Назначение

Механизм может служить заранее подготовленным **аварийным входом («бэкдором»)**,
когда VPN или другой основной способ доступа не работает из-за сбоя, маршрутизации
или ограничений сети. Он позволяет временно получить доступ к чувствительным
SSH, RDP, административным и другим сервисам, которые обычно закрыты от публичного
интернета. Сервис сохраняет свою обычную аутентификацию. Подготовьте и проверьте
этот путь заранее; UDP/WebRTC и сеть до сервера должны оставаться доступны.

## Работа клиента

1. Нажмите иконку расширения. На компьютере импортируйте выданный сервером JSON-файл
   или JSON-текст. На телефоне также доступны QR-камера, изображение и QR-текст.
2. Выберите профиль, нажмите ON и откройте защищённый сервис обычным клиентом.
3. Нажмите OFF для немедленного снятия разрешения своего IPv4. Простой без трафика
   к защищённому сервису также закрывает разрешение автоматически.
4. «Удалить профиль» удаляет секрет **только из этого браузера**. Для немедленного
   закрытия доступа сначала нажмите OFF. Удаление локальной копии не отзывает
   серверный секрет и не отменяет выданное разрешение. Оно истечёт по таймауту;
   администратор может отозвать секрет командой `revoke`.

Два разных внешних IPv4 с одним профилем не мешают друг другу: ON, OFF и простой
относятся к своей паре «профиль + IPv4». Устройства за одним внешним IPv4 разделяют
разрешение. Сообщение «отправлен» не является подтверждением сервера: проверить
доступ можно подключением к самому сервису.

Внешний IPv4 определяется через `stun:stun.cloudflare.com:3478` для каждой команды.
STUN получает IP, но не секрет и не подписанную команду. Администратор может задать
`ice_host`, `ice_source` и `stun_server` в JSON до передачи клиенту. Поле `ice_source`
содержит фиксированный внешний IPv4 и отключает STUN; при смене сети адрес нужно
обновить. UDP-knock и трафик сервиса должны выходить через один внешний IPv4.

## OpenWrt

Выберите APK своей архитектуры, скопируйте на роутер и установите:

```sh
apk add --allow-untrusted /tmp/knock-control-4.0.3-r1.apk
knock-control init --public-host 203.0.113.10 --interface eth1
knock-control issue --name Phone --ports 2222 --idle-timeout 600 --out /root/phone.json --qr-out /root/phone.png
```

Замените адрес и интерфейс на реальные. Имя WAN-устройства можно узнать через
`ubus call network.interface.wan status`. Передайте профиль по защищённому каналу
и импортируйте его **до** активации защиты административного порта:

```sh
knock-control activate
/etc/init.d/knock-control enable
/etc/init.d/knock-control-firewall enable
```

Стандартный конфиг — `/etc/config/knock-control`, права 0600. Секреты генерируются
на сервере. API и веб-клиент не устанавливаются, сертификат не создаётся. Все
административные действия выполняются локально через SSH/консоль.

Изменить таймаут конкретного профиля:

```sh
knock-control list
uci set knock-control.PROFILE_ID.idle_timeout='120'
uci commit knock-control
/etc/init.d/knock-control reload
knock-control export PROFILE_ID --out /root/phone.json
knock-control qr PROFILE_ID --out /root/phone.png
```

Замените `PROFILE_ID` на выданный ID. Перезагрузка настроек изменяет ревизии и
закрывает прежние разрешения; повторно экспортируйте и импортируйте профили.
Отзыв секрета закрывает разрешения всех его копий:

```sh
knock-control revoke PROFILE_ID
```

## Правила и пробросы

Работают на OpenWrt и Linux. Типы: `input` для сервера, `forward` для маршрутизируемого
доступа, `dnat` для проброса на внутренний IPv4. Порты и диапазоны задаются списком:

```sh
knock-control rule-set ssh_lan --type dnat --protocol tcp --ports 2222 --dest-ip 192.168.1.10 --dest-port 22
knock-control rule-set udp_range --type input --protocol udp --ports 11000-11100
knock-control rule-set ping --type input --protocol icmp
knock-control issue --name Phone --rules ssh_lan,udp_range,ping --idle-timeout 600 --out /root/phone.json --qr-out /root/phone.png
```

OpenWrt хранит определения в `config rule 'NAME'`, выбранные правила — в списке
`rules` профиля. Клиент их не редактирует. Для DNAT/FORWARD нужен обратный маршрут
через этот сервер/роутер; SNAT автоматически не добавляется. ICMP по умолчанию
разрешает echo-request. OFF и простой блокируют также установленные потоки.
IPv6 не поддерживается.

## Linux

Нужны libpcap, OpenSSL libcrypto, Python 3, systemd, iptables и ipset:

```sh
./scripts/build.sh
sudo ./scripts/install-server.sh
sudo knock-control init --public-host 203.0.113.10 --interface eth0
sudo knock-control issue --name Laptop --ports 22 --out /root/laptop.json
# Сначала передайте и импортируйте профиль.
sudo knock-control activate
sudo systemctl enable knock-control.service knock-control-firewall.service
```

Локальный конфиг — `/etc/knock-control/settings.json`. После изменений администратором
выполните `sudo knock-control apply`, затем экспортируйте и импортируйте новые
ревизии. Native CLI принимает файл явно: `./knockd.sh open --profile laptop.json`.
Для обычной последовательности TCP/UDP задайте свой внешний IPv4 в `public_ip`
этого файла; браузерный ICE определяет его через STUN.

## Обновление с 3.x

Установка останавливает и отключает `knock-control-api`, удаляет его службу/CGI
и больше не открывает порт управления в firewall. Секреты и ревизии сохраняются;
SQLite-журнал сохраняется вместе с защитой от повторов. Его прежнее имя
`api-replays.sqlite3` оставлено ради совместимости данных.

Старые ICE-профили v2 JSON/QR импортируются и преобразуются локально, без обращения
к прежнему URL. Новый экспорт v3 не содержит `server_url` или сертификата.
Новый QR — автономный `knock-control://import/#import=kc3_...`: сканируйте его
в клиенте. QR не открывает сайт knock-сервера. Старый сервер без ICE нужно обновить. Если ревизия или адрес профиля устарели,
экспортируйте его заново.

Firefox desktop/Android использует один подписанный XPI. Chromium/Chrome/Edge —
один ZIP для загрузки распакованного расширения. Для Chrome Android и других
браузеров без расширений есть отдельный статический ZIP: разместите его на любом
доверенном HTTPS-хостинге, установите/сохраните приложение и импортируйте профиль
внутри него. Knock-сервер этот сайт больше не раздаёт.

Интерфейс включает 10 языков, английский по умолчанию; иконка взята из профиля Mozilla.
[Установка расширений](doc/BROWSER_INSTALLATION_RU.md), [проверки 4.0.3](doc/RELEASE_4.0.3.md).
